Expand description

Stores the ID of keys published ahead of time

https://signal.org/docs/specifications/x3dh/

§Last-ID contract

The last_*_id getters return the id most recently issued, 0 meaning none yet. Generation starts one past that (increment + % PRE_KEY_MEDIUM_MAX_VALUE wrap, so ids are 1-based), and the set_last_* setters record the last id of the batch. Implementors MUST treat the setters as plain persistence: write the value, return. They MUST NOT advance, wrap, or otherwise mutate the id.

§Active-ID contract

set_active_* records the id the server has accepted. The store_*_pre_key_bundle methods do NOT set them; call mark_signed_pre_keys_active only after a successful upload, so clean_stale_pre_keys excludes the correct live key. The matching getters return None before the first upload.

fn signed_pre_keys_due_for_rotation<'life0, 'async_trait>( &'life0 self, ) -> Pin<Box<dyn Future<Output = Result<bool, SignalProtocolError>> + 'async_trait>>
where Self: 'async_trait, 'life0: 'async_trait,

Whether the signed and last-resort Kyber pre-keys are due for rotation.

Due if never rotated, or if the last rotation is older than PRE_KEY_ROTATION_INTERVAL.

One-time pre-keys are deliberately not considered: their replenishment is gated on the server’s remaining count, and the local count is not a usable proxy — the local pool stays full while the server hands its copies out.

Implementors may override this to use a different schedule.

Persist a rotated signed pre-key (and last-resort kyber key) and record the ids issued.

One-time keys are untouched: a signed rotation does not supersede them, so nothing is marked stale here.

Active ids are NOT set — call mark_signed_pre_keys_active after the upload succeeds.

fn store_one_time_pre_key_bundle<'life0, 'life1, 'life2, 'async_trait>( &'life0 mut self, pre_keys: &'life1 [PreKeyRecord], pq_pre_keys: &'life2 [KyberPreKeyRecord], ) -> Pin<Box<dyn Future<Output = Result<(), SignalProtocolError>> + 'async_trait>>
where Self: 'async_trait, 'life0: 'async_trait, 'life1: 'async_trait, 'life2: 'async_trait,

Persist a fresh batch of one-time pre-keys and record the ids issued.

Uploading one-time keys replaces the server’s set, so the batch being superseded is marked stale here: it is no longer offered, and ages out via clean_stale_pre_keys after the grace period.

Each pool is handled independently — a pool is only staled when keys are actually arriving to replace it, so passing an empty slice leaves that pool untouched rather than retiring every usable key in it.

fn mark_signed_pre_keys_active<'life0, 'life1, 'life2, 'async_trait>( &'life0 mut self, signed_pre_key: &'life1 SignedPreKeyRecord, pq_last_resort_key: &'life2 KyberPreKeyRecord, ) -> Pin<Box<dyn Future<Output = Result<(), SignalProtocolError>> + 'async_trait>>
where Self: 'async_trait, 'life0: 'async_trait, 'life1: 'async_trait, 'life2: 'async_trait,

Records the signed / last-resort ids the server has accepted as active, and stamps the rotation.

Call only after the upload succeeds. clean_stale_pre_keys uses these to preserve the live published keys; setting them beforehand risks pointing active at a key the server never accepted, and would start the rotation interval on keys the server never took.

fn clean_stale_pre_keys<'life0, 'async_trait>( &'life0 mut self, ) -> Pin<Box<dyn Future<Output = Result<(), SignalProtocolError>> + 'async_trait>>
where Self: 'async_trait, 'life0: 'async_trait,

Archive superseded signed / last-resort keys and delete stale one-time keys.

Signed and last-resort keys older than ARCHIVE_AGE are removed, all but the youngest and the currently active one. One-time keys marked stale longer than STALE_AGE are deleted while preserving at least ONE_TIME_MIN_COUNT.

Run only after a successful upload, so the active ids reflect server-confirmed keys.
