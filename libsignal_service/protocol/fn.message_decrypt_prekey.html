Expand description

Decrypt a PreKeySignalMessage from remote_address.

If a session for the incoming base key already exists, the inner SignalMessage is decrypted against that session directly. This covers both retransmitted pre-key messages and messages 1+ of the initial chain, which all carry the same base key. The peer’s identity is always trust-checked, but only saved for an active session. Messages on existing archived sessions cannot replace the stored identity; they are reported through IdentityKeyStore::record_received_identity instead. A new session always saves, even when it is placed in the archive (which only happens when its identity matches the active session’s). After the trust check, each receive makes exactly one of the two calls.

Otherwise this builds a candidate session from the pre-key material, AEAD-verifies the inner SignalMessage against the candidate, and only commits the session + consumes pre-keys + saves identity on AEAD success. This enforces the protocol invariant that a session is committed only after AEAD decrypts.
